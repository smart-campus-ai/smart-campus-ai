## Contexte

Les étudiants cherchent souvent des informations sur les services, procédures et installations du campus. Un assistant conversationnel permet d'y répondre sans créer de ticket. Ses réponses doivent provenir uniquement de la base de connaissances (RF03) et l'historique de session est conservé dans `chat-sessions` avec une durée de vie limitée (US08).

## User story

En tant qu'étudiant, je veux dialoguer avec un chatbot pour obtenir des informations relatives au campus, afin de trouver rapidement des réponses sur les services, procédures et installations.

## Critères d'acceptation

```gherkin
# language: fr
Fonctionnalité: US02 — Discussion avec le chatbot du campus

  Scénario: AC1 — Accès à l'interface de chat
    Étant donné un étudiant authentifié sur le portail
    Quand il ouvre l'assistant
    Alors une interface de chat accessible au clavier et aux lecteurs d'écran s'affiche

  Scénario: AC2 — Question en langage naturel
    Étant donné un étudiant dans l'interface de chat
    Quand il pose une question en langage naturel sur le campus
    Alors la question est envoyée à l'API de chat avec son token

  Scénario: AC3 — Réponse issue de la base de connaissances
    Étant donné un document indexé qui répond à la question
    Quand le chatbot répond
    Alors la réponse est construite uniquement à partir de la base de connaissances (RF03)
    Et elle cite la ou les sources utilisées

  Scénario: AC4 — Pas de réponse disponible
    Étant donné une question sans réponse dans la base de connaissances
    Quand le chatbot répond
    Alors il répond "je ne sais pas"
    Et il propose de créer un ticket de support (US10)

  Scénario: AC5 — Historique de session conservé
    Étant donné une conversation en cours
    Quand l'étudiant recharge la page dans la même session
    Alors les échanges précédents sont affichés
    Et ils sont stockés dans la table "chat-sessions" avec un attribut TTL renseigné (US08)

  Scénario: AC6 — Isolation des sessions
    Étant donné deux étudiants A et B
    Quand A demande l'historique d'une session appartenant à B
    Alors aucune donnée de B n'est renvoyée
```

## Exigences non fonctionnelles

- Temps de réponse p95 < 2000 ms hors génération longue, à mesurer par EN-84.
- Inférence dans l'UE (profil d'inférence inter-régions EU).
- Le contenu des conversations n'est jamais journalisé en clair.

## Notes techniques / décisions

- Fonction `chat` ; la session est rattachée au `sub` du JWT, jamais à un identifiant fourni par le client.
- Guardrail (EN-52) appliqué à chaque appel ; l'identifiant du modèle est une variable.

## Dépendances

- EN-51 — Knowledge Base
- EN-52 — Guardrail
- EN-53 — Table `chat-sessions`
- EN-32 — Authorizer Cognito

RF03 (confinement) s'appuie sur cette issue et la complète ; elle n'en est pas un prérequis.
