## Contexte

Quand l'assistant ne sait pas répondre (RF03), l'étudiant doit pouvoir créer un ticket sans ressaisir son problème. Le contexte de la conversation pré-remplit le formulaire de création (US04).

## User story

En tant qu'étudiant, je veux transformer une conversation chatbot non résolue en ticket de support, afin de ne pas ressaisir mon problème.

## Critères d'acceptation

```gherkin
# language: fr
Fonctionnalité: US10 — Escalade du chat vers un ticket

  Scénario: AC1 — Bouton d'escalade
    Étant donné une conversation en cours
    Quand l'étudiant consulte l'interface de chat
    Alors un bouton accessible "Créer un ticket" est disponible
    Et il est mis en avant quand le chatbot a répondu "je ne sais pas"

  Scénario: AC2 — Pré-remplissage du formulaire
    Étant donné une conversation non résolue
    Quand l'étudiant clique sur "Créer un ticket"
    Alors le formulaire US04 s'ouvre avec le titre et la description pré-remplis à partir du contexte de l'échange
    Et l'étudiant peut tout modifier avant de soumettre

  Scénario: AC3 — Validation inchangée
    Étant donné un formulaire pré-rempli
    Quand l'étudiant soumet
    Alors les mêmes règles de validation et de création que US04 s'appliquent

  Scénario: AC4 — Contexte limité à l'étudiant
    Étant donné une demande de pré-remplissage
    Quand le contexte est construit
    Alors seule la session de l'étudiant authentifié (sub du JWT) est utilisée
```

## Exigences non fonctionnelles

- Les PII masquées par le Guardrail restent masquées dans le pré-remplissage.
