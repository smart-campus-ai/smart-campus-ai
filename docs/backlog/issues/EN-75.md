## Contexte

Une modification faite hors OpenTofu (console, CLI) contredit NFR-01. Un plan nocturne en lecture seule détecte cette dérive et ouvre une issue.

## User story

En tant qu'équipe OPS, je veux une détection de dérive nocturne, afin d'être alerté de toute modification manuelle de l'infrastructure.

## Critères d'acceptation

```gherkin
# language: fr
Fonctionnalité: EN-75 — Détection de dérive

  Scénario: AC1 — Exécution planifiée
    Étant donné le workflow de dérive
    Quand il s'exécute chaque nuit
    Alors un plan en lecture seule ("-detailed-exitcode") est calculé pour chaque stack et environnement

  Scénario: AC2 — Issue en cas de dérive
    Étant donné un plan avec des différences
    Quand le workflow se termine
    Alors une issue labellisée "drift" est créée ou mise à jour avec le résumé (sans valeur sensible)

  Scénario: AC3 — Pas de bruit
    Étant donné un plan sans différence
    Quand le workflow se termine
    Alors aucune issue n'est créée et une issue "drift" ouverte pour cette stack est commentée comme résolue
```

## Exigences non fonctionnelles

- Utilise le rôle plan en lecture seule ; permissions GitHub limitées à `issues: write` pour ce job.

## Notes techniques / décisions

- Requis par NFR-01-AC3 : la priorité `could` est à réévaluer (voir plan de migration).
- Le rôle plan est restreint à `pull_request` : un `sub` supplémentaire pour le workflow planifié est à prévoir dans EN-13.
