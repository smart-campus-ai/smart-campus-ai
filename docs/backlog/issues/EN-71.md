## Contexte

La CI rejoue sur chaque PR le gate local `task check` et fournit les checks requis par les rulesets (EN-02). Les workflows eux-mêmes doivent respecter les règles de sécurité GitHub Actions du projet.

## User story

En tant qu'équipe OPS et QE, je veux une CI qui valide chaque PR, afin que rien ne soit fusionné sans lint, contrôles de sécurité et tests verts.

## Critères d'acceptation

```gherkin
# language: fr
Fonctionnalité: EN-71 — CI des PR

  Scénario: AC1 — Titre de PR conventionnel
    Étant donné une PR vers "develop"
    Quand son titre n'est pas un Conventional Commit valide (types et scopes de AGENTS.md) ou que le corps ne contient pas "Closes #n"
    Alors le check échoue

  Scénario: AC2 — Lint et formatage
    Étant donné une PR
    Quand la CI s'exécute
    Alors "tofu fmt -check", "tofu validate", tflint, actionlint et zizmor s'exécutent

  Scénario: AC3 — Sécurité
    Étant donné une PR
    Quand la CI s'exécute
    Alors Checkov (avec les politiques de "policies/"), Trivy et gitleaks s'exécutent et échouent sur un nouveau finding

  Scénario: AC4 — Tests unitaires et docs
    Étant donné une PR
    Quand la CI s'exécute
    Alors "tofu test" (unitaire) et la vérification terraform-docs s'exécutent

  Scénario: AC5 — Durcissement des workflows
    Étant donné les workflows
    Quand zizmor s'exécute
    Alors "permissions: {}" est déclaré au niveau supérieur, les jobs ont des permissions minimales
    Et "actions/checkout" utilise "persist-credentials: false"
    Et aucun "pull_request_target" ni entrée non fiable interpolée dans "run:" n'est présent

  Scénario: AC6 — Checks nommés de façon stable
    Étant donné les jobs de CI
    Quand EN-02 configure les rulesets
    Alors chaque check requis a un nom stable documenté
```

## Exigences non fonctionnelles

- Durée de la CI < 10 minutes sur une PR typique (cache des outils mise).
- Aucune authentification AWS dans ce workflow.

## Notes techniques / décisions

- Le workflow appelle les tâches du Taskfile pour rester identique au local.

## Dépendances

- EN-01 — Outillage

## Definition of Done

- [ ] AC vérifiés par une PR de démonstration en échec puis en succès (`EN-71-AC1 …`)
- [ ] `task check` vert en local et en CI
- [ ] Noms des checks requis transmis à EN-02
- [ ] Issue mise à jour avec une note d'avancement
