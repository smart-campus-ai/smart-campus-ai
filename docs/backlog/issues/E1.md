## Objectif

Poser les fondations AWS sur lesquelles toutes les autres briques s'appuient : state OpenTofu sécurisé, accès CI sans clé longue durée, chiffrement par domaine, baseline de sécurité et maîtrise des coûts.

## Périmètre

- Inspection du compte workshop (région, droits, services disponibles ou déjà actifs).
- Bootstrap (seul apply local, exécuté par un humain) : bucket de state, clé KMS, chiffrement client du state et du plan, verrou natif.
- Fédération OIDC GitHub → AWS : rôles plan (lecture seule) et apply, permissions boundary.
- Clés KMS par domaine (`data`, `logs`, `ai`).
- Baseline sécurité avec interrupteurs (CloudTrail, GuardDuty, Security Hub FSBP, Config, Access Analyzer).
- Budget AWS et alertes de coût.

## Critères de sortie

- [ ] Le state de chaque stack est stocké chiffré (SSE-KMS + chiffrement OpenTofu `enforced`) avec verrou natif.
- [ ] La CI s'authentifie uniquement par OIDC ; aucune clé d'accès longue durée n'existe.
- [ ] Tout rôle IAM créé par OpenTofu porte la permissions boundary du projet.
- [ ] Les clés KMS `data`, `logs`, `ai` existent avec rotation activée et politique explicite.
- [ ] Les résultats du spike EN-11 sont documentés (ADR ou note) et ont levé les incertitudes de région/services.
- [ ] Toutes les issues enfants sont fermées.
