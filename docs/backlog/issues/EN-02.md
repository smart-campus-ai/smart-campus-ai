## Contexte

Le dépôt `smart-campus-ai/smart-campus-ai` doit appliquer le workflow défini dans AGENTS.md : `develop` (intégration, défaut) et `main` (production) protégées, squash-merge, PR conventionnelles, board GitHub Projects. Les rulesets exigent les checks fournis par EN-71 : ils sont activés en second temps (ordre de réalisation, étape 2).

## User story

En tant qu'équipe OPS, je veux une gouvernance GitHub configurée et reproductible, afin que chaque changement suive le même circuit de revue et soit tracé.

## Critères d'acceptation

```gherkin
# language: fr
Fonctionnalité: EN-02 — Gouvernance GitHub

  Scénario: AC1 — Labels
    Étant donné le dépôt
    Quand on liste les labels
    Alors la taxonomie de git-workflow.md existe avec couleur et description
    Et les labels par défaut de GitHub ont été supprimés

  Scénario: AC2 — Templates
    Étant donné la création d'une issue ou d'une PR
    Quand on choisit un template
    Alors les sections attendues (issue : Contexte… Definition of Done ; PR : Résumé… Checklist DoD) sont proposées en français

  Scénario: AC3 — CODEOWNERS
    Étant donné une PR qui modifie "infra/", ".github/", "services/" ou "frontend/"
    Quand elle est ouverte
    Alors la revue du rôle propriétaire est demandée automatiquement

  Scénario: AC4 — Rulesets develop et main
    Étant donné les checks requis de EN-71 disponibles
    Quand on pousse directement, force-pousse ou supprime "develop" ou "main"
    Alors l'opération est refusée
    Et une PR vers "develop" n'est fusionnable qu'en squash, historique linéaire, checks verts
    Et une PR vers "main" n'est acceptée que depuis "develop" ou release-please (check "guard-main")

  Scénario: AC5 — Environnements
    Étant donné les environnements GitHub "dev" et "prod"
    Quand un job cible "prod"
    Alors il attend une approbation manuelle d'un réviseur désigné
    Et "prod" n'est déployable que depuis "main"

  Scénario: AC6 — Board Projects
    Étant donné le board GitHub Projects v2
    Quand on l'ouvre
    Alors les champs Status, Priority, Epic, Role, Size existent avec les vues "par Status", "par Epic" et "OPS/QE"
```

## Exigences non fonctionnelles

- Configuration reproductible : scripts `gh` ou fichiers versionnés dans le dépôt, pas de réglage non documenté.

## Notes techniques / décisions

- La création des labels et la migration des issues suivent `docs/backlog/migration-plan.md`.
- AC4 peut être livré dans une seconde PR une fois EN-71 fusionnée.
