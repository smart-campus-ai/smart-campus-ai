## Contexte

L'infrastructure possède la configuration, le pipeline applicatif possède le code (`ignore_changes` sur le code dans OpenTofu). Ce pipeline construit les artefacts produits par SE, publie les Lambdas, bascule l'alias `live`, publie la SPA et invalide CloudFront. C'est ce qui permet à l'équipe SE de déployer.

## User story

En tant qu'équipe OPS, je veux un pipeline de déploiement applicatif avec rollback, afin que l'équipe SE livre en dev et en prod sans toucher à l'infrastructure.

## Critères d'acceptation

```gherkin
# language: fr
Fonctionnalité: EN-74 — Déploiement applicatif

  Scénario: AC1 — Artefacts Lambda
    Étant donné une fusion qui modifie "services/<fonction>/"
    Quand le pipeline s'exécute
    Alors l'artefact arm64 de la fonction est construit, publié et une nouvelle version est créée

  Scénario: AC2 — Bascule de l'alias
    Étant donné une nouvelle version publiée
    Quand les smoke tests de pré-bascule passent
    Alors l'alias "live" pointe sur cette version

  Scénario: AC3 — SPA et invalidation
    Étant donné une fusion qui modifie "frontend/"
    Quand le pipeline s'exécute
    Alors la SPA est publiée dans le bucket et une invalidation CloudFront est lancée

  Scénario: AC4 — Rollback
    Étant donné une version déployée défaillante
    Quand le rollback est déclenché
    Alors l'alias "live" revient à la version précédente et la SPA précédente est republiée

  Scénario: AC5 — Pas de dérive OpenTofu
    Étant donné un déploiement applicatif terminé
    Quand un plan OpenTofu est calculé
    Alors il ne montre aucune différence sur le code des fonctions

  Scénario: AC6 — Droits minimaux
    Étant donné le rôle de déploiement applicatif
    Quand on lit sa politique
    Alors il ne peut que mettre à jour le code, publier des versions et modifier les alias des fonctions "sc-<env>-*", écrire dans le bucket SPA et invalider la distribution
```

## Exigences non fonctionnelles

- prod via l'environnement GitHub `prod` avec approbation.
- Smoke tests (EN-83) exécutés après chaque déploiement.

## Notes techniques / décisions

- Le build dépend du runtime choisi par SE ; le pipeline fournit une action composite par type d'artefact.
- Rôle de déploiement applicatif distinct du rôle apply infra, créé dans le bootstrap ou la foundation (à trancher).
