## Contexte

`main` est la production. Les releases passent de `develop` à `main` via une PR de release ; release-please génère les tags et `CHANGELOG.md` à partir des Conventional Commits.

## User story

En tant qu'équipe OPS, je veux des releases automatisées et une garde sur `main`, afin que la production ne reçoive que des versions identifiées et documentées.

## Critères d'acceptation

```gherkin
# language: fr
Fonctionnalité: EN-76 — Releases

  Scénario: AC1 — PR de release
    Étant donné des commits conventionnels fusionnés sur "develop"
    Quand release-please s'exécute
    Alors une PR de release met à jour "CHANGELOG.md" et la version

  Scénario: AC2 — Tag
    Étant donné la PR de release fusionnée sur "main"
    Quand le workflow se termine
    Alors un tag et une release GitHub sont créés

  Scénario: AC3 — Garde de main
    Étant donné une PR vers "main" depuis une branche autre que "develop" ou release-please
    Quand le check "guard-main" s'exécute
    Alors il échoue et la PR ne peut pas être fusionnée
```

## Exigences non fonctionnelles

- Permissions du workflow limitées (`contents: write`, `pull-requests: write` au niveau du job).

## Notes techniques / décisions

- Le nom du check `guard-main` est utilisé par le ruleset `main` (EN-02).

## Dépendances
