## Contexte

La soutenance du workshop repose sur une démonstration de bout en bout. Elle doit être scénarisée, reposer sur des données de démo fictives et pouvoir être rejouée sans intervention manuelle sur AWS.

## User story

En tant que BA et QE, je veux préparer le scénario, les données et le script de démo, afin de présenter la plateforme de façon fiable et convaincante.

## Critères d'acceptation

```gherkin
# language: fr
Fonctionnalité: EN-95 — Préparation de la démo

  Scénario: AC1 — Scénario
    Étant donné "docs/"
    Quand on lit le scénario de démo
    Alors il couvre : création de ticket, suivi, gestion admin, escalade SLA, chat avec réponse et refus, escalade chat → ticket, KPI, un blocage WAF

  Scénario: AC2 — Données de démo
    Étant donné l'environnement de démo
    Quand le script de données est exécuté
    Alors des utilisateurs, tickets et documents fictifs sont chargés, sans donnée personnelle réelle

  Scénario: AC3 — Jeu de questions
    Étant donné le chatbot
    Quand on rejoue le jeu de questions de démo
    Alors les questions couvertes reçoivent une réponse sourcée et les questions hors périmètre reçoivent "je ne sais pas"

  Scénario: AC4 — Répétition
    Étant donné la démo complète
    Quand elle est répétée en dev
    Alors elle se déroule dans le temps imparti sans action manuelle sur la console AWS
```

## Exigences non fonctionnelles

- Le délai SLA est réduit en dev pour la démo par configuration, pas par modification du code.
- Les e-mails de démo vont vers des identités SES vérifiées.
