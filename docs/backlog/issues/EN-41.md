## Contexte

Huit fonctions Lambda sont prévues (`tickets`, `kpi`, `chat`, `escalation`, `notifier`, `kb-sync`, `kpi-aggregator`, `pre-token`). Un module générique garantit les mêmes invariants pour toutes. L'infrastructure possède la configuration, le pipeline applicatif possède le code.

## User story

En tant qu'équipe OPS, je veux un module `lambda-service` réutilisable, afin que chaque fonction soit déployée avec les mêmes garanties de sécurité et d'observabilité.

## Critères d'acceptation

```gherkin
# language: fr
Fonctionnalité: EN-41 — Module lambda-service

  Scénario: AC1 — Architecture et tracing
    Étant donné une instance du module
    Quand le plan est calculé
    Alors l'architecture est "arm64" et le tracing est "Active"

  Scénario: AC2 — Un rôle par fonction
    Étant donné deux instances du module
    Quand le plan est calculé
    Alors chacune a son propre rôle IAM portant la permissions boundary du projet
    Et la politique est construite à partir des déclarations passées en entrée, sans "Action = *"

  Scénario: AC3 — Log group explicite
    Étant donné une instance du module
    Quand le plan est calculé
    Alors un groupe "/aws/lambda/<nom>" est créé, chiffré par la clé fournie, avec la rétention fournie

  Scénario: AC4 — Alias live
    Étant donné une instance du module
    Quand le plan est calculé
    Alors un alias "live" existe et c'est lui qui est exposé en sortie pour les intégrations

  Scénario: AC5 — Échecs asynchrones
    Étant donné "enable_dlq" à true
    Quand le plan est calculé
    Alors une file SQS chiffrée reçoit les échecs d'invocation asynchrone

  Scénario: AC6 — Code géré par le pipeline applicatif
    Étant donné un nouveau code déployé par EN-74
    Quand un plan OpenTofu est recalculé
    Alors aucune différence n'apparaît sur filename, source_code_hash, s3_key ou s3_object_version

  Scénario: AC7 — Validations
    Étant donné une rétention de logs non autorisée ou un nom vide
    Quand le plan est calculé
    Alors la validation de variable échoue
```

## Exigences non fonctionnelles

- Concurrence réservée paramétrable.
- Aucune variable d'environnement ne contient de secret (références SSM uniquement).

## Notes techniques / décisions

- Runtime et handler en variables (choix SE) ; artefact de remplacement au premier apply.
- Pas de VPC (ADR).

## Dépendances

- EN-13 — Permissions boundary
- EN-14 — Clés KMS
