## Objectif

Faire de Git la seule source de vérité : toute modification d'infrastructure et d'application est validée, planifiée, approuvée et déployée par la CI, avec traçabilité de bout en bout (exigence NFR-01).

## Périmètre

- CI sur les PR : titre conventionnel, lint, sécurité, tests unitaires, docs.
- Plan OpenTofu sur les PR via OIDC lecture seule, commentaire, Infracost.
- Apply GitOps : `develop` → dev, `main` → prod avec approbation, plan figé.
- Déploiement applicatif : artefacts Lambda, alias, SPA, invalidation, rollback.
- Détection de dérive, releases (release-please, changelog, garde de `main`).

## Issues enfants

- NFR-01 — Traçabilité GitOps et Infrastructure as Code
- EN-71 — CI : titre de PR, lint, sécurité, tests unitaires, docs
- EN-72 — Plan sur les PR (OIDC lecture seule), commentaire, Infracost
- EN-73 — Apply GitOps : develop → dev, main → prod avec approbation, plan figé
- EN-74 — Déploiement applicatif : artefacts Lambda, alias, SPA, invalidation, rollback
- EN-75 — Détection de dérive nocturne → issue
- EN-76 — Releases : release-please, changelog, garde de `main`

## Critères de sortie

- [ ] Aucun apply hors CI, sauf `infra/bootstrap`.
- [ ] Une fusion sur `develop` déploie dev ; une release sur `main` déploie prod après approbation.
- [ ] Chaque déploiement est relié à sa PR et à son issue.
- [ ] Les issues `must` sont fermées ; NFR-01 est vérifiée.
