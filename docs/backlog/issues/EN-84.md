## Contexte

L'exigence de performance est un temps de réponse inférieur à 2 s, traduit en seuil mesurable : p95 < 2000 ms. Les tests k6 vérifient ce seuil sur les parcours principaux.

## User story

En tant que QE, je veux des tests de performance k6 avec seuils, afin de vérifier objectivement l'exigence de temps de réponse.

## Critères d'acceptation

```gherkin
# language: fr
Fonctionnalité: EN-84 — Performance k6

  Scénario: AC1 — Seuil p95
    Étant donné les scénarios création de ticket, liste de mes tickets et KPI
    Quand "task perf ENV=dev" s'exécute avec la charge définie
    Alors le p95 de chaque scénario est inférieur à 2000 ms

  Scénario: AC2 — Taux d'erreur
    Étant donné la même exécution
    Quand elle se termine
    Alors le taux de requêtes en erreur (hors 429 attendus) est inférieur au seuil défini

  Scénario: AC3 — Profil de charge documenté
    Étant donné "tests/perf/"
    Quand on lit le README
    Alors le nombre d'utilisateurs virtuels, la durée et les hypothèses (taille du campus) sont décrits

  Scénario: AC4 — Échec explicite
    Étant donné un seuil non respecté
    Quand k6 se termine
    Alors le code retour est non nul et le rapport indique le scénario fautif
```

## Exigences non fonctionnelles

- Charge compatible avec les limites de débit WAF et le throttling (utilisateurs de test distincts ou seuils dev adaptés).

## Notes techniques / décisions

- Le chat est mesuré à part (temps de génération), avec un seuil à valider par le PO.
