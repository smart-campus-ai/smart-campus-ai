## Contexte

Les étudiants disposent d'un compte institutionnel Microsoft. La fédération Entra ID (OIDC) dans Cognito évite un second mot de passe. Elle dépend d'une inscription d'application dans le tenant de l'école ; sans elle, la plateforme reste sur des utilisateurs Cognito natifs. La fonctionnalité est derrière `enable_entra_federation`.

## User story

En tant qu'utilisateur, je veux lier l'authentification au SSO Microsoft de l'école, afin de me connecter de manière sécurisée avec mon compte institutionnel.

## Critères d'acceptation

```gherkin
# language: fr
Fonctionnalité: US06 — SSO Microsoft Entra ID

  Scénario: AC1 — Connexion via Entra ID
    Étant donné "enable_entra_federation" à true et l'application inscrite dans le tenant de l'école
    Quand l'utilisateur choisit "Se connecter avec Microsoft"
    Alors il est authentifié par Entra ID puis reçoit des tokens émis par Cognito

  Scénario: AC2 — Filtrage du domaine approuvé
    Étant donné un compte Entra ID dont l'e-mail n'appartient pas au domaine approuvé
    Quand il tente de se connecter
    Alors le trigger pre-token refuse l'émission du token
    Et aucun accès à l'API n'est possible

  Scénario: AC3 — Création ou association du profil
    Étant donné un utilisateur du domaine approuvé qui se connecte pour la première fois
    Quand l'authentification réussit
    Alors un profil Cognito fédéré est créé et rattaché au groupe "student" par défaut
    Et une connexion ultérieure réutilise le même profil

  Scénario: AC4 — Tokens acceptés par l'API
    Étant donné un utilisateur fédéré connecté
    Quand il appelle l'API avec son token
    Alors l'authorizer Cognito natif l'accepte comme un utilisateur natif

  Scénario: AC5 — Repli sans fédération
    Étant donné "enable_entra_federation" à false
    Quand le plan est calculé
    Alors aucun fournisseur d'identité OIDC n'est créé
    Et les utilisateurs Cognito natifs se connectent normalement
```

## Exigences non fonctionnelles

- Aucun secret client Entra dans le code, les tfvars ou les outputs : stocké en SSM SecureString ou Secrets Manager.
- L'e-mail n'est jamais journalisé en clair par le trigger pre-token.

## Notes techniques / décisions

- IdP OIDC Cognito + trigger `pre-token` (filtrage du domaine, mapping des groupes).
- Le domaine approuvé est une variable.
- Prérequis hors équipe : inscription de l'application par l'administrateur du tenant de l'école.

## Dépendances

- EN-31 — Cognito
- EN-32 — Authorizer Cognito
- EN-41 — Module `lambda-service` (trigger `pre-token`)
