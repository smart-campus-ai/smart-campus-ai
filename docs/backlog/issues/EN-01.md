## Contexte

Toute l'équipe (OPS, QE, AS, SE) doit travailler avec les mêmes versions d'outils et les mêmes commandes. C'est la première brique du chemin critique : la CI (EN-71) réutilise les tâches définies ici.

## User story

En tant qu'équipe OPS, je veux une chaîne d'outils épinglée et des tâches communes, afin que chaque membre et la CI exécutent exactement les mêmes contrôles.

## Critères d'acceptation

```gherkin
# language: fr
Fonctionnalité: EN-01 — Outillage du dépôt

  Scénario: AC1 — Outils épinglés
    Étant donné le fichier ".mise.toml"
    Quand on le lit
    Alors chaque outil (tofu, tflint, checkov, trivy, terraform-docs, gitleaks, lefthook, task, hurl, k6...) a une version exacte

  Scénario: AC2 — Installation en une commande
    Étant donné un poste neuf avec mise installé
    Quand on exécute "task setup"
    Alors la chaîne d'outils est installée et les hooks lefthook sont actifs

  Scénario: AC3 — Gate local
    Étant donné le dépôt
    Quand on exécute "task check"
    Alors fmt, lint, sécurité, tests unitaires et contrôle des docs s'exécutent et le code retour reflète le résultat

  Scénario: AC4 — Hooks pre-commit et commit-msg
    Étant donné un commit contenant un secret factice ou un message non conventionnel
    Quand on tente de committer
    Alors gitleaks ou commitlint bloque le commit

  Scénario: AC5 — Style homogène
    Étant donné ".editorconfig"
    Quand un éditeur ouvre un fichier du dépôt
    Alors l'encodage, les fins de ligne et l'indentation sont imposés
```

## Exigences non fonctionnelles

- Fonctionne sous Linux, macOS et Windows (postes de l'équipe).
- Les tâches ne lisent jamais `.env` ni les credentials AWS.

## Notes techniques / décisions

- Tâches attendues : `setup`, `check`, `test:unit`, `test:integration`, `plan`, `docs`, `smoke`, `perf` (cf. AGENTS.md).
- commitlint avec les types et scopes de AGENTS.md.
