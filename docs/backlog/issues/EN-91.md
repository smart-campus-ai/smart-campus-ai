## Contexte

Chaque décision contraignante de l'architecture v3 doit être tracée par un ADR au format MADR (contexte, décision, alternatives, conséquences, impact sécurité et coût), justifié par AWS Well-Architected.

## User story

En tant qu'architecte, je veux rédiger les ADR initiaux, afin que l'équipe et les évaluateurs comprennent et puissent contester chaque choix structurant.

## Critères d'acceptation

```gherkin
# language: fr
Fonctionnalité: EN-91 — ADR initiaux

  Scénario: AC1 — Couverture des décisions
    Étant donné "docs/adr/"
    Quand on liste les ADR
    Alors il en existe un pour : OpenTofu, compte unique dev/prod, pas de domaine, API REST + WAF régional plutôt qu'API HTTP, authorizer Cognito natif, pas de VPC, S3 Vectors, Scheduler SLA

  Scénario: AC2 — Format MADR
    Étant donné un ADR
    Quand on le lit
    Alors il contient contexte, décision, alternatives, conséquences, impact sécurité et impact coût

  Scénario: AC3 — Statut et lien
    Étant donné un ADR
    Quand on le lit
    Alors il a un statut (proposé, accepté, remplacé) et référence les issues concernées

  Scénario: AC4 — Index
    Étant donné "docs/adr/"
    Quand on ouvre l'index
    Alors chaque ADR y figure avec son numéro, son titre et son statut
```
