## Contexte

Le state OpenTofu contient des informations sensibles. Le bootstrap (`infra/bootstrap`) crée le backend pour toutes les stacks ; c'est le seul apply local, exécuté par un humain (Paul).

## User story

En tant qu'équipe OPS, je veux un backend de state chiffré et verrouillé, afin que les stacks soient appliquées de façon sûre et concurrente par la CI.

## Critères d'acceptation

```gherkin
# language: fr
Fonctionnalité: EN-12 — Bootstrap du state

  Scénario: AC1 — Bucket de state sécurisé
    Étant donné le bucket de state
    Quand le plan est calculé
    Alors Block Public Access est entièrement activé, l'ownership est "BucketOwnerEnforced", le versioning est activé
    Et le chiffrement par défaut est SSE-KMS avec la clé de state
    Et la politique refuse toute requête sans "aws:SecureTransport"

  Scénario: AC2 — Clé KMS du state
    Étant donné la clé KMS du state
    Quand le plan est calculé
    Alors la rotation est activée et la politique de clé est explicite (pas de principal "*" sans condition)

  Scénario: AC3 — Verrou natif
    Étant donné un backend.hcl d'environnement
    Quand on l'inspecte
    Alors "use_lockfile = true", "encrypt = true" et "kms_key_id" sont définis
    Et aucune table DynamoDB de verrou n'est utilisée

  Scénario: AC4 — Chiffrement client OpenTofu
    Étant donné chaque stack
    Quand on inspecte le bloc "encryption"
    Alors un key provider "aws_kms" et la méthode "aes_gcm" chiffrent le state et le plan avec "enforced = true"

  Scénario: AC5 — Cycle de vie
    Étant donné le bucket de state
    Quand le plan est calculé
    Alors une règle de cycle de vie expire les versions non courantes après la durée configurée
```

## Exigences non fonctionnelles

- Les outputs du bootstrap ne contiennent aucun secret.
- Procédure d'apply local documentée (runbook EN-94).

## Notes techniques / décisions

- Clé de state séparée des clés de domaine (EN-14) pour limiter le rayon d'impact.
- State du bootstrap : stratégie à décrire dans l'ADR (local chiffré puis migré, ou backend créé puis `init -migrate-state`).
