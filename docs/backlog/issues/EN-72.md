## Contexte

Chaque PR qui touche `infra/` doit montrer le plan OpenTofu et son impact de coût avant revue. Le plan s'exécute avec le rôle OIDC en lecture seule (EN-13), dont la confiance est limitée à `pull_request`.

## User story

En tant qu'équipe OPS, je veux un plan et une estimation de coût commentés sur chaque PR d'infrastructure, afin de revoir l'impact réel d'un changement avant de le fusionner.

## Critères d'acceptation

```gherkin
# language: fr
Fonctionnalité: EN-72 — Plan sur les PR

  Scénario: AC1 — Plan par stack et environnement
    Étant donné une PR qui modifie "infra/"
    Quand le workflow s'exécute
    Alors un plan est calculé pour chaque stack concernée en dev (et en prod pour une PR de release)

  Scénario: AC2 — Rôle en lecture seule
    Étant donné le job de plan
    Quand il s'authentifie
    Alors il assume le rôle plan via OIDC avec "id-token: write" limité à ce job

  Scénario: AC3 — Commentaire
    Étant donné un plan calculé
    Quand le job se termine
    Alors un commentaire unique est créé ou mis à jour sur la PR avec le résumé du plan
    Et il ne contient aucune valeur sensible

  Scénario: AC4 — Coût
    Étant donné un plan calculé
    Quand Infracost s'exécute
    Alors la différence de coût mensuel est ajoutée au commentaire

  Scénario: AC5 — Plan chiffré
    Étant donné le fichier de plan
    Quand il est conservé en artefact
    Alors il est chiffré par le bloc "encryption" OpenTofu
```

## Exigences non fonctionnelles

- Les PR depuis des forks n'obtiennent pas d'identifiants AWS.
- La clé d'API Infracost est un secret GitHub, jamais affiché.

## Notes techniques / décisions

- Pas de `pull_request_target`.

## Dépendances

- EN-71 — CI
- EN-13 — Rôle plan OIDC
