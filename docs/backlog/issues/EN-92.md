## Contexte

L'architecture v3 doit être représentée visuellement pour l'équipe et la soutenance : un diagramme drawio éditable et une version diagram-as-code versionnée.

## User story

En tant qu'architecte, je veux un diagramme d'architecture v3 à jour, afin que chacun visualise les flux, les frontières de sécurité et les dépendances.

## Critères d'acceptation

```gherkin
# language: fr
Fonctionnalité: EN-92 — Diagramme d'architecture v3

  Scénario: AC1 — Contenu
    Étant donné le diagramme
    Quand on le lit
    Alors il montre CloudFront et ses deux comportements, les deux web ACL, l'API REST, Cognito, les Lambdas, les tables, les buckets, Bedrock, Scheduler, SES/SNS et l'observabilité

  Scénario: AC2 — Deux formats
    Étant donné "docs/architecture/"
    Quand on liste les fichiers
    Alors un fichier drawio et une source diagram-as-code avec son rendu existent

  Scénario: AC3 — Flux de sécurité
    Étant donné le diagramme
    Quand on le lit
    Alors les frontières de confiance, le chiffrement KMS par domaine et les flux d'identité sont repérables

  Scénario: AC4 — Accessibilité
    Étant donné le rendu
    Quand il est publié
    Alors il est accompagné d'une description textuelle
```

## Exigences non fonctionnelles

- Rendu reproductible depuis la source.

## Notes techniques / décisions

- Mettre à jour le diagramme à chaque ADR qui modifie l'architecture.
