## Contexte

Le Guardrail Bedrock est le mécanisme de confinement de l'assistant (RF03) et de protection des données (US08) : sujets interdits, masquage des PII, filtre d'attaque par prompt et vérification d'ancrage contextuel avec seuils.

## User story

En tant qu'équipe OPS, je veux un Guardrail Bedrock versionné et paramétrable, afin que chaque réponse de l'assistant soit filtrée, ancrée et sans PII.

## Critères d'acceptation

```gherkin
# language: fr
Fonctionnalité: EN-52 — Guardrail Bedrock

  Scénario: AC1 — Sujets interdits
    Étant donné la liste de sujets interdits fournie en variable
    Quand le plan est calculé
    Alors chaque sujet est déclaré dans le Guardrail

  Scénario: AC2 — Masquage des PII
    Étant donné le Guardrail
    Quand le plan est calculé
    Alors les types de PII configurés (au minimum e-mail, téléphone, nom) sont masqués en entrée et en sortie

  Scénario: AC3 — Attaque par prompt
    Étant donné le Guardrail
    Quand le plan est calculé
    Alors le filtre d'attaque par prompt est activé sur les entrées

  Scénario: AC4 — Ancrage contextuel
    Étant donné les variables de seuil d'ancrage et de pertinence
    Quand le plan est calculé
    Alors la vérification d'ancrage contextuel est activée avec ces seuils
    Et une valeur hors [0, 1] fait échouer la validation

  Scénario: AC5 — Messages de blocage
    Étant donné une réponse bloquée
    Quand elle est renvoyée
    Alors le message est "je ne sais pas" avec la proposition de créer un ticket

  Scénario: AC6 — Version publiée
    Étant donné une modification du Guardrail
    Quand l'apply se termine
    Alors une nouvelle version est publiée et son identifiant est passé à "chat" par variable d'environnement
```

## Exigences non fonctionnelles

- Chiffrement du Guardrail par la clé `ai`.
