## Contexte

L'architecture v3 retient une API Gateway REST régionale (et non HTTP API) : sans domaine, l'URL `execute-api` reste joignable, et seule une API REST accepte une web ACL régionale, la validation des requêtes par modèles JSON Schema, le throttling par stage et par méthode et les plans d'usage. Le contrat est défini dans `packages/contracts` (OpenAPI).

## User story

En tant qu'équipe OPS, je veux une API REST régionale générée depuis le contrat OpenAPI, avec validation, throttling et observabilité, afin d'exposer les services de façon sûre et mesurable.

## Critères d'acceptation

```gherkin
# language: fr
Fonctionnalité: EN-33 — API REST régionale

  Scénario: AC1 — Ressources et méthodes
    Étant donné le contrat OpenAPI de "packages/contracts"
    Quand le plan est calculé
    Alors chaque opération correspond à une méthode intégrée en proxy à l'alias "live" de la fonction concernée

  Scénario: AC2 — Validation des requêtes
    Étant donné une méthode avec un modèle JSON Schema
    Quand une requête au corps non conforme est envoyée
    Alors API Gateway répond 400 sans invoquer la Lambda

  Scénario: AC3 — Throttling
    Étant donné le stage
    Quand le plan est calculé
    Alors des limites de débit et de rafale sont définies au niveau du stage et des méthodes sensibles (chat, création de ticket)

  Scénario: AC4 — Logs d'accès JSON
    Étant donné le stage
    Quand une requête est traitée
    Alors un log d'accès JSON est écrit dans un groupe chiffré par la clé "logs", avec rétention
    Et il ne contient ni en-tête "Authorization" ni corps de requête

  Scénario: AC5 — X-Ray
    Étant donné le stage
    Quand le plan est calculé
    Alors le tracing X-Ray est activé

  Scénario: AC6 — Permissions d'invocation scopées
    Étant donné les permissions Lambda
    Quand on les lit
    Alors chaque permission est limitée à l'ARN d'exécution de l'API et de la méthode concernée
```

## Exigences non fonctionnelles

- Point de terminaison REGIONAL ; latence p95 < 2000 ms de bout en bout (EN-84).

## Notes techniques / décisions

- Authorizer Cognito : EN-32 ; web ACL régionale : RF04.
- L'URL de l'API est passée à EN-21 comme origine `/api/*`.
- Décision « API REST plutôt qu'HTTP API » documentée par ADR (EN-91).

## Dépendances

- EN-41 — Module `lambda-service`
- EN-14 — Clés KMS
- Contrat OpenAPI initial dans `packages/contracts` (SE / QE)
